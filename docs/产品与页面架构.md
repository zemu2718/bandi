> 关联文档：[《页面低保真线框图》](./页面低保真线框图.md) · [《技术架构》](./技术架构.md) · [《本地服务与前端联调契约》](./本地服务与前端联调契约.md)

## 1. 文档职责

本文定义 Bandi Desktop 的产品定位、领域边界、信息架构、关键流程与首版验收标准。界面和实现统一围绕：

```text
Team → Agent → 可选的 Team-scoped TaskBrief
```

旧开发数据要求用户在设置中重置 Bandi状态，不建设迁移界面、运行时双读或兼容投影。

## 2. 产品定位

### 2.1 一句话定位

Bandi Desktop 用于可视化管理不同 AI Agent 各自的长期配置。用户按 Team 组织多个不同职责的长期 Agent；每个 Agent 都有独立 AgentPackage、长期 Memory 和可追溯版本。用户通过安全写入维护 Bandi 受管配置，再回到自己选择的 AI 编程工具使用这些 Agent。当前内置工具固定为 Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes 和 Pi。

### 2.2 核心用户

- 个人用户：直接使用 Personal Team 管理长期 Agent；
- 小团队负责人：按 Team 管理 Agent、TaskBrief 和共享配置；
- 多 Agent 用户：在所选外部 AI 编程工具中自行选择当前任务的参与 Agent；Bandi 不记录参与或协作关系。

### 2.3 核心价值

1. 一眼看清多个不同职责的长期 Agent 分别属于哪个 Team，以及各自拥有哪些独立长期配置；
2. 安全编辑 Bandi 受管配置，并保留基线、版本、外部变化和恢复证据；
3. 按需整理同一 Team 的 TaskBrief，不把简报扩张为任务执行系统；
4. 让 Agent 长期 Memory 能可靠写入并保留可追溯 Revision；
5. 将所选上下文交给用户选择的外部 AI 编程工具，而不在 Desktop 内复制执行体验。

## 3. 产品责任边界

### 3.1 Desktop 负责

- Team 与长期 Agent 管理；
- 可选的 Team-scoped TaskBrief；
- AgentPackage 与显式共享资产；
- Agent 长期 Memory 的安全写入、Revision 和恢复；
- 普通配置的安全保存、历史、本地 Backup 与重置 Bandi；
- 在固定 `/tools` 页面提供九工具本机有限检测、固定官方安装入口、固定配置位置 reveal，以及 Client Launch v3 类型化启动交接；Bandi 不自动安装工具或集成。

### 3.2 外部 AI 编程工具负责

- 当前任务的下达与澄清；
- 参与 Agent 选择与任务协作；
- 工具调用、Todo、日志和执行反馈；
- 权限请求与批准；
- 冲突处理、审批、汇报和最终验收；
- 当前 Session 的全部交互。

### 3.3 产品不做

- 任务执行器、完整任务管理系统或看板；
- 聊天客户端、内嵌终端或 Session 管理器；
- 人员调度、执行审批、实时监控或 Agent View；
- Desktop SOP 运行引擎；
- 通用进程启动器、opener、文件管理器 API 或 Shell；
- 凭据、Token、Cookie、私钥或终端内容管理器；
- 接受任意路径，枚举、扫描或读取宿主配置内容；
- 除用户在 `/tools` 显式触发的固定配置位置 reveal 外，访问或修改宿主用户目录。

TaskBrief 不是可执行 Task。它只属于一个 Team，记录标题、目标与背景、约束和期望产出；不持久化 Agent，也没有进度、Todo、Assignment、审批、日志、汇报或验收状态。

## 4. 安全承诺

- Bandi 应用内只读取和展示 Bandi 自有受管配置；
- Bandi 不接受用户目录或路径作为业务输入，不枚举、不扫描、不读取宿主配置内容；
- 唯一宿主目录例外是用户在 `/tools` 显式触发的固定配置位置 reveal；后端依据稳定工具 ID 解析 allowlist 目标；
- AI 工具本机命令不接受路径或 URL，不暴露通用 opener、文件 API、Shell 或脚本，不修改、移动、重命名、清空或删除宿主目录内容；
- Agent 配置、Agent 长期 Memory、Revision、Backup 和 UI 偏好均位于 Bandi 自有数据边界；
- 删除 Agent、删除 Team、恢复 Backup 和重置 Bandi只处理 Bandi 自有数据；
- 预览、确认和结果文案必须同时说明“会处理什么”和“不会处理什么”，不得以技术实现词替代安全承诺。

## 5. 产品主线

### 5.1 首次使用

Personal Team `team-personal` 始终存在。无 Agent 且未选择稍后设置时显示首次欢迎页；已有 Agent 的健康冷启动直接进入当前 Team 的 Agent 列表；无 Agent 但已选择稍后设置时进入普通配置状态。读取失败、诊断和未完成 recovery 始终优先于首次欢迎。

```text
打开 Bandi
→ 创建产品研发团队，或添加、导入单个 Agent，也可稍后设置
→ 创建团队前预览 1 个 Team 和 4 个 Agent
→ 确认后按顺序创建；初始不授予权限，也不自动引用共享资产
→ 查看或调整长期配置
→ 保存
→ 在所选外部 AI 编程工具中继续
```

首次添加的单个 Agent 默认归属 Personal Team。批量创建中途未完成时保留已创建内容，并通过既有配置状态与单 Agent recovery 显示待处理项；Bandi 不自动回滚，也不在重启后自动补齐其余预设 Agent。TaskBrief 按需创建。

### 5.2 日常配置管理

```text
切换 Team
→ 选择 Agent
→ 查看身份与长期配置
→ 修改单项配置
→ 保存并查看明确结果
```

只有真实需要时才展示来源、Diff、共享影响、外部变化、冲突或高风险确认。普通保存不引入草稿审批或发布流程。

### 5.3 可选 TaskBrief

```text
当前 Team
→ 新建 TaskBrief（可选）
→ 填写目标与背景、约束、期望产出
→ 保存或归档
```

TaskBrief 始终由 Team 持有，不关联 Agent，不记录执行状态，也不形成调度关系。

### 5.4 九工具独立页面

| 工具 | 固定入口 |
| --- | --- |
| Claude Code | plugin |
| Claude Desktop | MCPB；转到官方 UI 安装，状态为 `degraded` |
| Codex | `~/.agents/skills` |
| Gemini | `~/.gemini/extensions` |
| Grok | `~/.grok/skills` |
| OpenCode | `~/.config/opencode/skills` |
| OpenClaw | `~/.openclaw/skills` |
| Hermes | `~/.hermes/skills` |
| Pi | `~/.pi/agent/skills` |

九个工具分别在固定 `/tools` 页面展示。macOS 端围绕固定 catalog 从受限 PATH 与明确列出的包管理器、版本管理器目录发现工具，对命中项执行固定版本参数，并从固定官方源查询最新版本；安装状态与版本状态独立表达。用户可在预览真实影响并独立确认后升级可安全锚定的单个工具；无法确认安装来源时只提供官方更新入口。Bandi 不读取配置正文、不接受任意路径或命令、不下载并执行远程安装脚本；官方页面打开、reveal 或升级进程退出成功均不表示工具已加载、已初始化或可运行。

### 5.5 外部继续使用

```text
选择 Team
→ 选择该 Team 下的 Agent
→ 选择该 Team 下的 TaskBrief（可选）
→ 提交受控启动请求
→ 根据 `outcome` 与 `contextDelivery` 在外部工具继续，或手动粘贴上下文
```

Client Launch v3 在启动时临时选择 Team、active Agent 和可选同 Team TaskBrief，由后端重取受管数据并构造上下文。请求只接受固定工具、Adapter、终端枚举与稳定 ID，不接受调用方提供的路径、cwd、prompt、正文、bundle ID、executable、argv、环境变量、stdin 或脚本。结果以 `outcome` 区分 `terminal_launch_requested | application_launch_requested | manual_context_required`，并以 `contextDelivery` 区分 `initial_prompt | manual_copy | none`；请求已提交不表示工具已完成初始化、登录或任务已开始，Bandi 不读取输出、不保存 PID、不管理 Session。

## 6. 核心领域模型

```text
Team
├── Agent
└── TaskBrief（可选）

Agent
├── AgentPackage / 长期配置资产
├── Agent 长期 Memory
└── ConfigRevision / MemoryRevision
```

### 6.1 Team 与 Agent

- 每个 Agent 必须且只能属于一个 Team；
- Agent 的 `teamId` 是唯一归属事实；
- Personal Team 始终存在且不可删除；
- Team 切换后，页面只管理该 Team 下的 Agent、TaskBrief 和 Team-scoped 长期资产；
- Agent 生命周期为 active、inactive、archived；停用或归档保留配置、长期 Memory 和历史；永久删除使用独立高风险确认。

### 6.2 TaskBrief

- 每个 TaskBrief 必须且只能属于一个 Team；
- `teamId` 是唯一归属事实；
- 字段固定为标题、目标与背景、约束、期望产出、归档时间；
- 不包含 Agent、负责人、参与者、优先级、进度或执行结果；
- 切换 Team 后不得展示或选择其他 Team 的 TaskBrief。

### 6.3 AgentPackage 与配置资产

受管 Agent 使用稳定 `agent-id` 的独立 AgentPackage。主要资产包括：

```text
identity / instructions / context / rules / skills / mcp
permissions / sop / hooks / commands
```

共享资产是独立于 AgentPackage、供 Agent 复用的 Team-scoped 资产池，首版可管理 Skills、MCP、Rules 和 SOP。资产中心只扫描 Bandi 自有受管共享根，支持用户显式新增、通过系统选择器导入受管副本，以及带 baseline、影响确认、原子写、Revision 和 recovery 的正文更新；不读取或扫描宿主工具目录，也不保存导入源的绝对路径。Agent 仅保存稳定资产 ID 引用，资产详情依据当前引用图反向展示使用中的 Agent；来源、Team 登记与引用关系不能被复制成第二份可漂移事实。

### 6.4 Agent 长期 Memory

Memory 只有 **Agent 长期** 一类，通过受限目标、baseline 复核、原子写入和重读验证直接保存，成功后生成 MemoryRevision。

Memory 归对应 Agent 所有，不由 Team、TaskBrief 或共享资产持有。任务过程、聊天、Todo、工具输出和临时摘要不会自动进入长期 Memory。

### 6.5 配置版本与证据

普通配置保存使用：

```text
baseline
→ 校验
→ 原子写入 Bandi 自有数据
→ 重读验证
→ write receipt
→ ConfigRevision
→ recovery（如需要）
```

Backup 是独立设置能力，不进入每次保存主线，也不能替代 baseline、外部变化保护或安全写入。

## 7. 信息架构

### 7.1 全局 Shell

```text
┌────────────────┬────────────────┬─────────────────────────┐
│ Team 标识/名称  │ 当前 Team Agent │ 页面内容                │
│ 需求池          │ 最近/全部 Agent │                         │
│ Agent           │                │                         │
│ 资产            │                │                         │
│ 设置            │ Agent 栏收展    │                         │
│ 一级菜单收展    │                │                         │
└────────────────┴────────────────┴─────────────────────────┘
```

一级菜单固定为：

- 需求池
- Agent
- 资产
- 设置（底部）

左上 Team 入口负责切换 Team、编辑当前 Team 和新建 Team。一级菜单与 Agent 二级栏分别收展，互不改变对方状态。配置状态保留为 `/` 系统落点，不占用一级菜单；存在待处理项时从顶栏进入。正常且已有 Agent 时，冷启动直接进入 Agent 列表。

### 7.2 页面清单

| 页面 | 主要目的 | 默认范围 |
| --- | --- | --- |
| 配置状态 | 按需展示真实配置问题和待处理恢复，不复制执行期状态 | 当前 Team / 全局必要事项 |
| Agent 列表 | 选择、创建和管理长期 Agent | 当前 Team |
| Agent 详情 | 查看身份、配置、Agent 长期 Memory 和历史 | 单个 Agent |
| 资产 | 扫描、创建、导入和更新独立长期资产，查看 Agent 使用关系与诊断 | 当前 Team |
| 需求池 | 管理轻量 TaskBrief | 当前 Team |
| AI 工具 `/tools` | 九工具独立入口、本机有限检测、官方安装页、固定配置位置 reveal 与启动 | 全局 |
| 设置 | 个性化、Backup、重置 Bandi | 全局 |

### 7.3 响应式 Shell

- Desktop：可收展一级菜单 + 当前 Team Agent 二级栏 + 页面内容；
- Compact：一级菜单与 Agent 二级栏各自紧凑显示；
- Hidden：Agent 二级栏可在个性化设置中显式隐藏；
- body 不得横向滚动，宽表格、Diff 和代码在自身容器内滚动。

## 8. 关键页面行为

### 8.1 Team 切换器

- 支持键盘打开、方向键选择、Enter 确认和 Escape 关闭；
- 关闭后焦点恢复；
- 切换后清除不属于新 Team 的 Agent 和 TaskBrief 选择；
- 不显示在线、运行、Session、未读或任务执行状态。

### 8.2 Agent 页面

- Agent 列表只显示当前 Team；
- 深链 Agent 不属于 current Team 时，同步到该 Agent 的 Team 或进行确定性安全回退；
- 创建 Agent 默认归属 current Team，不重复询问 Team；
- 编辑页按配置职责拆分；
- 来源、Diff、历史和冲突按需打开。

### 8.3 需求池页面（内部 TaskBrief）

- 创建时默认使用 current Team；
- 只展示当前 Team 的简报；
- “待交接 / 已归档”只由 `archivedAt` 派生，不表达执行完成状态；
- 页面不出现负责人、参与 Agent、执行进度、Todo、日志、审批或验收控件。

### 8.4 AI 工具页与 Client Launch v3 对话框

- `/tools` 固定展示九个工具及各自详情，不提供自定义工具或方案 CRUD；
- 本机检测、官方安装页、固定配置位置 reveal 和启动入口均由稳定工具 ID 驱动；
- 启动时 Team 与 Agent 必选，TaskBrief 可选；这些选择只用于本次请求，不持久化参与关系；
- 切 Team 清理 Agent 和 TaskBrief 选择，提交前再次校验全部同 Team关系；
- Escape 关闭并恢复焦点；
- 前端按 `outcome` 与 `contextDelivery` 显示“启动请求已发送”“应用打开请求已发送”或“上下文已复制，请手动粘贴”；
- 不展示或提交路径、任意命令与进程参数，不显示 PID、输出或 Session 状态。

## 9. 保存、删除与恢复体验

| 结果 | 页面行为 |
| --- | --- |
| `saved` | 使用 canonical 返回值更新状态并退出编辑 |
| `unchanged` | 退出编辑，不生成新版本 |
| `baseline_changed` | 保留 draft，展示 base/current/proposed |
| `confirmation_required` | 展示真实影响，确认后用同一业务请求重试 |
| `validation_failed` | 保留输入，在字段或文件位置展示修复建议 |
| `save_failed` | 保留 draft，如实展示 Bandi 自有数据状态和 recovery 入口 |

删除与恢复必须先预览真实影响并要求精确确认。统一安全文案：

> 仅处理 Bandi 自有数据。Bandi 不接受、访问、扫描、修改或删除任意用户目录。

重置提交后当前窗口立即终止编辑并自动请求重新打开 Bandi；若重启调度失败，只显示手动重新打开兜底，不回滚已提交的重置。重置只处理 Bandi 自有数据，不以用户目录或其中内容作为目标、保留项或校验对象。

## 10. 视觉与交互基线

- 视觉克制、清楚，以黑白灰语义 Token 为主；
- 强调色只用于主操作、选中态与焦点环；
- 默认信息密度低，详细配置渐进展开；
- 图标按钮有可访问名称，装饰图标不进入无障碍树；
- 表单使用可见 label，错误紧邻字段并通过 ARIA 关联；
- Dialog、Popover、Sheet 支持键盘、Escape、可见焦点和合理焦点恢复；
- 遵循 `prefers-reduced-motion`；
- 亮暗主题都保持可读对比度。

## 11. 首版必须实现

- Personal Team 与 Team 切换器；
- Agent 单 Team 归属、当前 Team Agent 隔离与 Agent 生命周期；
- Team-scoped TaskBrief；
- AgentPackage 全配置族；
- 仅 Agent 长期 Memory，直接通过安全保存链写入；
- baseline、外部变化、原子写、ConfigRevision 与 recovery；
- 本地 Backup 与高风险 Factory Reset；
- 固定 `/tools` 九工具页面及 Client Launch v3 typed outcomes / `contextDelivery` 合同；
- 不接收或操作任意用户目录的硬边界；
- Team-scoped Shell、窄屏和键盘可访问性；
- Rust / TypeScript / Schema / fixture / Tauri capability 一致。

## 12. 验收标准

- 新用户无需创建 TaskBrief 即可创建第一个 Agent；
- 切换 Team 后 Agent、TaskBrief 和 Team-scoped 长期资产不串 Team；
- Personal Team 始终存在且不可删除；
- TaskBrief 不持久化 Agent，也没有执行期状态；
- Memory 只有 Agent 长期一类，完成受限直接写入、Revision 和 recovery；
- `/tools` 只做固定候选检测、打开固定官方安装页、reveal 已存在的固定配置位置和受控启动；Client Launch v3 只接受固定枚举与 Team、Agent、可选 TaskBrief 稳定 ID，并返回 typed `outcome` / `contextDelivery`；
- 所有删除与恢复只处理 Bandi 自有数据；
- Bandi 不接受、访问、扫描、修改或删除任意用户目录；
- Web、Rust、E2E、真实 Chromium 和 diff 检查通过。
