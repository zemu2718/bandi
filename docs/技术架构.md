# 班底技术架构

> 文档版本：v4.0
> 更新日期：2026-09-09
> 状态：当前有效架构（长期领域 v4）
> 关联文档：[《产品与页面架构》](./产品与页面架构.md) · [《页面低保真线框图》](./页面低保真线框图.md) · [《本地服务与前端联调契约》](./本地服务与前端联调契约.md)

## 1. 文档目标

本文定义 Bandi Desktop 作为 9 个内置 AI 编程工具长期 Agent / 配置管理器的当前有效技术边界、领域事实、存储、安全写入和宿主衔接方式。内置工具固定为 Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes 和 Pi。实现只维护一套长期领域 v4 运行时，不保留旧领域的双读、投影、别名或 fallback。

Bandi 管理长期配置资产；用户自己的 AI 编程工具负责当前任务的执行期交互。Desktop 不承担任务执行、聊天、内嵌终端、人员调度、审批、日志或 Session 监控。

## 2. 技术原则

1. **Team → Agent 是唯一主线。** TaskBrief 仅作为可选的 Team-scoped 轻量上下文，其他内容均为长期资产。
2. **稳定 ID 是跨存储身份。** 前端不提交可信路径或通用进程参数。
3. **文件与 SQLite 各司其职。** 文件保存长期配置正文，SQLite 保存领域关系、索引、Revision 和恢复元数据。
4. **先读后写。** 所有写入先解析目标和基线，再校验、原子替换、重读验证并记录 Revision。
5. **显式授权。** Team 归属不自动扩大 Agent 长期权限；执行期批准只在 CLI 中发生。
6. **失败保持原事实。** 不用备份代替安全写入，不用乐观 UI 冒充持久化成功。
7. **旧开发数据直接重置。** 旧非零数据库版本不迁移；删除与恢复只处理 Bandi 自有数据。Bandi 不接受、访问、扫描、修改或删除任意用户目录。

## 3. 技术栈与发布形态

- Web：React 19、TypeScript strict、React Router、Vite、Tailwind CSS v4、Radix UI。
- Desktop：Tauri 2、Rust。
- 持久化：SQLite/WAL、受管 AgentPackage 文件、受限 Revision 与 Backup 目录。
- 测试：Vitest、Testing Library、Rust 单元/集成测试、WebdriverIO/Tauri E2E、真实 Chromium 验收。

纯 Web 可以展示界面和页面内存演示，但不得伪装真实发现、保存、备份或外部上下文交接。真实本机能力只由 Tauri command 暴露。

## 4. 总体架构

```text
React Web
  ├── Team-scoped 页面与编辑状态
  ├── 类型化 contracts
  └── Tauri invoke bridge
          │
Rust Local Service
  ├── Domain Store（长期领域 v4）
  ├── AgentPackage discovery / projection
  ├── Restricted Config Writer
  ├── Agent Long-term Memory Service
  ├── Backup / Factory Reset
  └── Client Launch v3 context adapter
          │
Bandi 自有存储
  ├── SQLite / WAL
  ├── ~/.bandi/agents/agt_{agentId}/
  └── Bandi revisions / backups
```

Bandi 的文件系统边界仅限 Bandi 自有存储；不接受用户目录作为领域数据，不访问、扫描、修改或删除任意用户目录。

### 4.1 Rust Local Service 职责

- 校验所有跨进程输入、稳定 ID、枚举、长度、状态与实体关系；
- 生成或重取 canonical 领域事实；
- 发现、解析和投影配置资产；
- 执行 Bandi 自有存储内的路径边界、symlink 和 owner 校验；
- 执行 baseline、受限原子写、write receipt、Revision 和 recovery；
- 管理 Agent 长期 Memory 的安全写入、Revision 与 recovery；
- 管理本地 Backup 与 Factory Reset；
- 仅通过 Client Launch v3 准备上下文；不调用客户端、终端或外部进程。

### 4.2 Web 职责

- 展示当前 Team 下的 Agent、可选 TaskBrief 和长期资产；
- 管理页面 draft、编辑器状态、确认与结构化错误；
- 只以 Rust 返回的 canonical 结果更新持久化状态；
- 不把整个前端 `State` 变成跨进程协议；
- 不构造路径、命令、进程参数或执行期上下文正文。

## 5. 当前领域事实

```text
Team
├── Agent
└── TaskBrief（可选）
```

- `FullAgent.teamId` 是 Agent 单 Team 归属的唯一事实源。
- `Team.memberAgentIds` 是后端聚合或前端派生索引，不可成为第二事实源。
- `team-personal` 始终存在且不可删除。
- TaskBrief 必须属于一个 Team，不持久化 Agent，不产生执行状态。

SQLite 当前 `user_version` 为 `17`，长期领域快照 `schemaVersion` 为 `4`。检测旧非零开发数据库时返回明确的恢复出厂要求，不执行数据迁移。

### 6.2 发现与投影

`discover_config` 只接收 `requestId`。发现范围仅为 Bandi 受管 AgentPackage；前端不提交路径或目录。

发现结果区分物理 `SourceContainer` 与逻辑 `SourceAsset`，并返回稳定资产 ID、双哈希、解析状态、可写性、引用图和诊断。历史外部引用不进入配置发现，也不再支持新增；Plugin cache 只作为证据，不是普通写回或恢复目标。


## 7. 普通配置保存

```text
load editor
→ 服务签发 baselineRef
→ 页面编辑 draft
→ save_config(assetId, expectedOwner, change, expectedBaseline, baseContent)
→ 重新解析目标与 owner
→ 双哈希基线复核
→ 类型与权限校验
→ restricted atomic write
→ 重读验证
→ write receipt
→ ConfigRevision
```

结果固定为：

- `saved`：写入、验证、Revision 均成功；
- `unchanged`：语义无变化，不生成 Revision；
- `baseline_changed`：返回 base/current/proposed，保留 draft；
- `confirmation_required`：长期权限扩大需独立确认；
- `validation_failed`：结构化诊断；
- `save_failed`：保留原文件或如实返回 revision pending recovery。

不提供通用 force。恢复历史版本也必须基于当前 baseline 走同一安全写入链，并生成新的 Revision。


## 8. 存储与恢复

### 8.1 SQLite/WAL

SQLite 保存 Team、TaskBrief、Agent 索引、Revision 元数据、恢复操作和 Backup 清单。跨实体更新在单个事务内维护引用完整性。

AgentPackage 文件和 SQLite 不宣称跨介质 ACID。涉及两者的 Agent 创建、身份编辑和永久删除先写 recovery operation，再按可恢复阶段提交；失败时依据真实 hash 与 live/quarantine 路径继续，不覆盖不一致内容。

### 8.2 Backup

本地 Backup 是独立设置能力，只保护用户明确选择的受管配置文件。创建、预览和恢复均使用类型化 command、内容哈希和完整性校验。恢复前创建 `pre_restore` 快照；Backup 不替代普通保存的 baseline 与原子写。

凭据、Token、Cookie、私钥、钥匙串数据、终端输出和执行过程永不进入 Backup。远程 Git 只允许 Private 仓库；Agent 长期 Memory 进入远程备份前必须单独确认。

### 8.3 Factory Reset

Factory Reset 使用 preview + fingerprint + 精确确认 + quarantine/rollback。它只清理 Bandi 自有数据库、受管 AgentPackage、Revision、Backup 和白名单 UI 偏好。删除与恢复都不得接受用户目录参数，也不得访问、扫描、修改或删除任意用户目录。成功后返回 `requiresRestart: true`。

## 9. Agent 长期 Memory

Memory 仅有 `agent_long_term`，canonical 路径固定为 `AgentPackage/memory/long-term.md`。它属于单个 Agent，不存在其他范围、继承或项目投影。

写入链固定为：

```text
resolve agent target
→ baseline 复核
→ restricted atomic write
→ 重读验证
→ write receipt
→ MemoryRevision
→ recovery
```

Memory 直接通过 Local Service 安全保存。baseline 变化必须拒绝覆盖并返回三方内容。

## 10. Client Launch v3

`request_client_launch_v3` 是唯一上下文准备合同：

```ts
type RequestClientLaunchV3 = {
  clientId: BuiltInClientId
  adapterId: ClientAdapterId
  terminalId: TerminalId
  intent: 'start_with_context'
  teamId: Id
  agentId: Id
  taskId?: Id
}
```

后端重新验证 Team、active Agent、成员关系以及可选的同 Team TaskBrief。v3 只准备上下文，不接受或解析路径、cwd、目录 ID、prompt、TaskBrief 正文、terminal、bundle ID、executable、argv、环境变量、stdin、脚本或通用进程参数。

Local Service 不访问或扫描用户目录，不调用客户端、终端或外部进程，不执行命令，不读取输出、不保存 PID、不管理 Session。结果只表达上下文是否准备完成。

## 11. 长期资产与 CLI 执行边界

SOP 等配置只作为 Agent 长期资产保存，Desktop 不选择任务参与者、不派发、不运行。Team 归属不自动扩大 Agent 长期权限；当前任务协作和一次性权限批准由 Claude Code CLI 处理。

## 12. 前端架构与 UI 基线

前端状态包含 `teams`、`currentTeamId`、`agents`、`taskBriefs` 等 canonical 集合。Team 切换使用 `SELECT_TEAM`；current Team 回退顺序为当前有效 Team、Personal Team、首个 Team、空值。

一级菜单：

```text
任务简报 / Agent / 资产
底部：设置 / 一级菜单展开或收起 / 主题
```

左上 Team 入口展开时显示名称与文字标识，紧凑时只显示标识；标识默认由名称派生 1–2 个字符，也可随 Team 持久化文字覆盖与五色预设，不接受图片或任意颜色。Radix 菜单负责 Team 切换、编辑当前 Team 和新建 Team。一级菜单使用 `Shell` 局部 `expanded / compact` 状态，宽屏默认展开、窄屏默认收起，不进入持久化偏好。

Agent 二级栏只显示当前 Team Agent，并继续由 `UiPreferences.mainMenuLayout`、`SET_MAIN_MENU_LAYOUT` 和 `resolveMainMenuLayout` 独立控制 `expanded / compact / hidden`；其展开或收起入口位于二级栏自身。两级菜单状态不得互相推导或覆盖。

`/tasks` 任务简报页复用 TaskBrief 列表—详情，只以 `archivedAt` 派生“待交接 / 已归档”。`/` 保留首次欢迎、hydration 和恢复等系统落点；TaskBrief 默认继承 current Team，创建表单不重复询问 Team。上下文准备默认只展示 Team 和 Agent，可选 TaskBrief 在“添加上下文”中渐进展开。

UI 必须支持键盘、Escape、可见焦点、合理焦点恢复、亮暗主题、窄屏降级和无 body 横向滚动。

## 13. Tauri command 边界

当前长期领域入口包括：

```text
load_long_term_domain_snapshot_v4
save_team_v4 / remove_team_v4
save_task_brief_v4 / remove_task_brief_v4
```

配置与 Memory 入口包括发现、编辑、安全保存、Revision 和 Recovery。备份与重置使用独立 command。上下文准备只暴露 `request_client_launch_v3`。

新增 command、plugin、capability、文件系统或进程权限前，必须证明其直接服务于长期配置管理，并保持最小参数、最小权限和最小暴露面。

## 14. 工程结构原则

生产文件原则上不超过 500 行；超过 800 行必须按业务职责拆分。React 页面分离编排、业务逻辑、状态和可复用 UI；Rust command 保持薄层。拆分不得制造纯转发包装、单实现抽象或循环依赖。

优先复用现有模块：

- `domain_store.rs`：长期领域 v4 事实与校验；
- `local_service.rs`：发现、配置保存和 Bandi 自有存储安全；
- `memory_target.rs` / `memory_service.rs`：Agent 长期 Memory；
- `factory_reset.rs` / `backup_service/`：恢复；
- `ai_adapters.rs`：Client Launch v3；
- `state.tsx` / `domain-selectors.ts`：Team-scoped 前端状态。

## 15. 技术验收标准

- 运行时仅保留长期领域 v4，无旧领域双写、投影、路径 fallback 或 command；
- Personal Team 稳定存在，每个 Agent 恰属一个 Team；TaskBrief 只属于 Team；
- Bandi 不接受、访问、扫描、修改或删除任意用户目录，删除与恢复只处理 Bandi 自有数据；
- Memory 仅 Agent 长期空间，并完成 Direct Write → Revision → Recovery；
- 普通配置保存覆盖 baseline、外部变化、原子写、write receipt、Revision 与 recovery；
- Client Launch v3 仅准备上下文，不接受路径、命令或执行期正文，不调用客户端、终端或外部进程；
- Web、Rust、合同、E2E 和生成的 Tauri capability/permissions 保持一致；
- lint、typecheck、test、build、Rust checks、E2E 与 `git diff --check` 全部通过。
