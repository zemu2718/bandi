> 文档版本：v3.0
> 更新日期：2026-09-08
> 状态：Team-scoped Shell 当前有效线框契约
> 关联文档：[《产品与页面架构》](./产品与页面架构.md) · [《技术架构》](./技术架构.md)

## 1. 线框目标与边界

本文描述 Bandi Desktop 当前的页面结构、默认信息密度、关键交互和响应式降级。Bandi 可视化管理不同 AI Agent 各自的长期配置：多个不同职责的长期 Agent 按 Team 组织，各自拥有独立配置和长期 Memory，并在用户选择的 AI 编程工具中使用。当前内置工具固定为 Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes 和 Pi。默认主线只有：

```text
Team → Agent → 可选的 Team-scoped TaskBrief
```

线框不引入任务执行、聊天、内嵌终端、人员调度、审批、Todo、日志、监控、汇报、验收或 Session 状态。TaskBrief 只是一份 Team-scoped 轻量简报。

Bandi 只处理 Bandi 自有数据，不接受、访问、扫描、修改或删除任意用户目录。所有页面、空态、确认和结果文案都必须遵守此边界。

## 2. 页面地图

```text
全局 Shell

├── Agent                        /agents
│   └── 创建                     /agents/new
│   └── Agent 详情               /agents/:agentId
├── 资产                         /assets
├── AI 工具                      /tools
└── 设置                         /settings

└── 配置状态 / 首次欢迎 / 恢复    /
```

一级菜单固定为“需求池 / Agent / 资产 / AI 工具”，设置固定在底部。Team 菜单提供切换、编辑当前 Team 和新建 Team。配置状态保留为系统落点，不占用一级菜单；存在待处理项时从顶栏进入。正常且已有 Agent 时，冷启动直接进入 Agent 列表。一级菜单与 Agent 二级栏分别收展。

## 3. S-00 全局 Shell

### Desktop

```text
┌──────────────────┬──────────────────┬──────────────────────────┐
│ [独] 独立工作室⌄  │ 当前 Team Agent   │ 页面标题                  │
│ 需求池            │ [头像] Agent A    │ 说明          主操作      │
│ Agent             │ [头像] Agent B    ├──────────────────────────┤
│ 资产              │                  │ 页面内容                  │
│ AI 工具           │ [收起 Agent 栏]   │                           │
│ 设置              │                  │                           │
│ 切换到深色        │                  │                           │
│ [收起侧栏]        │                  │                           │
└──────────────────┴──────────────────┴──────────────────────────┘
```

规则：

- 左上入口直接表达当前 Team；一级菜单收起时只显示 1–2 字符 Team 标识；
- Team 菜单用于切换 Team、编辑当前 Team 和新建 Team；
- 一级菜单宽屏默认展开、窄屏默认收起；
- Agent 二级栏只显示当前 Team 的 Agent；
- 最近访问仅用于当前 Team 内排序，不表达在线、运行、Session 或未读；
- 一级菜单与 Agent 二级栏各自提供收展入口，互不改变对方状态；
- 设置不属于 Team 次级对象；
- 页面 body 不横向滚动。

### Team 切换器

```text
┌────────────────────────┐
│ 个人班底          当前  │
│ 独立工作室              │
├────────────────────────┤
│ 编辑当前 Team           │
│ 新建 Team               │
└────────────────────────┘
```

交互：

- Enter/Space 打开，方向键选择，Enter 确认，Escape 关闭；
- 关闭后焦点回到触发按钮；
- 切换 Team 后进入 `/agents`；
- 清理不属于新 Team 的 Agent 和 TaskBrief 选择；
- 单 Team 时仍保留当前 Team 与次级入口；
- 空数据时 Personal Team 作为确定性回退。

```text

└──────────────────────────────────────────────────┘
```

| 状态 | UI |
| --- | --- |
| 已保存 | 使用服务 canonical 结果更新并退出编辑 |
| 无变化 | 退出编辑，不显示新版本 |
| 外部变化 | 保留 draft，展示 base/current/proposed |
| 需要确认 | 展示真实权限影响，确认后重试 |
| 格式错误 | 错误紧邻字段或文件位置，保留输入 |
| 保存失败 | 说明 Bandi 自有数据状态与恢复入口，保留 draft |

不提供“强制覆盖”。

## 13. E-01 AI 工具与启动

固定 `/tools` 页面为九个内置工具提供独立入口。

```text
┌──────────────────┬───────────────────────────────────────────┐
│ 已安装 / 未安装   │ Claude Code                    已检测到    │
│ 全部              │ 本机工具：只检查固定安装候选               │
│                  │ 上下文启动：可携带所选上下文启动            │
│ Claude Code      │ 固定配置位置：.claude                     │
│ Claude Desktop   │ [重新检查] [在文件管理器中显示] [启动]      │
│ Codex …          │ 未检测到时：[查看官方安装方式]              │
└──────────────────┴───────────────────────────────────────────┘
```

- 检测仅检查后端固定候选，不运行工具、不扫描 PATH、不读取配置正文；
- 官方安装按钮只打开后端固定 URL，不自动下载、安装工具或集成；
- reveal 只显示已存在的固定配置位置，成功不表示工具已安装、已加载或可运行；
- 浏览器环境不执行本机检测、reveal 或启动。

启动 Dialog：

```text
┌──────────────────────────────────────────────────┐
│ 在 Claude Code 中启动                             │
├──────────────────────────────────────────────────┤
│ Team        独立工作室                            │
│ Agent       研究助手                              │
│ 需求        不附加                                │
│                                                  │
│ [取消]                         [启动]              │
└──────────────────────────────────────────────────┘
```

规则：

- Team 与 active Agent 必填，TaskBrief 可跳过；选择只服务本次启动，不持久化参与关系；
- 切 Team 清空 Agent 和 TaskBrief 选择；提交前再次校验三者同 Team；
- 请求只包含固定工具、Adapter、终端枚举和稳定 ID，不接受调用方提供的路径、cwd、prompt、正文、bundle ID、executable、argv、环境变量、stdin 或脚本；
- `outcome` 为 `terminal_launch_requested | application_launch_requested | manual_context_required`；`contextDelivery` 为 `initial_prompt | manual_copy | none`；
- 页面分别显示“启动请求已发送”“应用打开请求已发送”或“上下文已复制，请手动粘贴”；请求已提交不等于工具已初始化、登录或任务已开始；
- Bandi 不读取输出、不保存 PID、不跟踪或管理 Session。

### Factory Reset 预览

```text
重置 Bandi

不会处理：任意用户目录或其中的文件
```

重置提交后当前窗口立即终止编辑并自动重新打开 Bandi；若自动重新打开失败，只显示手动重新打开兜底。Backup 不代替普通配置保存和版本。恢复 Backup 与重置 Bandi 都只处理 Bandi 自有数据。

## 15. 统一状态与文案

### 配置状态

- 已保存
- 无变化
- 外部已修改
- 需要确认
- 格式需要调整
- 保存失败
- 版本记录待恢复

### 启动交接状态

- 启动请求已发送
- 应用打开请求已发送
- 上下文已复制，请手动粘贴
- 请求被拒绝
- 尚未尝试

不得把请求已提交写成工具已初始化、已登录、任务已开始或 Session 已启动。

### 安全文案

删除和恢复统一使用：

> 仅处理 Bandi 自有数据，不处理宿主工具目录。

AI 工具页单独使用：

> Bandi 只检查固定安装候选，可打开固定官方安装页面或显示固定配置位置；不会自动安装，也不会读取宿主配置内容。

## 18. 已确认决策

1. Team → Agent → 可选 Team-scoped TaskBrief 是唯一产品主线。
2. Personal Team 始终存在且不可删除。
3. 每个 Agent 必须且只能属于一个 Team。
4. 每个 TaskBrief 必须且只能属于一个 Team，不持久化 Agent。
5. 一级菜单为需求池、Agent、资产、AI 工具，设置固定在底部。
6. Memory 仅为 Agent 长期，直接通过安全保存链写入并生成 Revision。
7. `/tools` 是固定九工具的独立页面，提供有限检测、官方安装入口、固定配置位置 reveal 和启动。
8. Client Launch v3 以 typed `outcome` / `contextDelivery` 表达受控启动或手动交接，不管理 Session。
9. Bandi 不自动安装工具或集成，不扫描 PATH，不读取宿主配置正文。
10. 应用内只查看 Bandi 自有配置；宿主目录只允许用户显式触发的固定 allowlist 安装或 reveal，不接受路径、不扫描、不读取宿主配置内容。
11. 删除与恢复只处理 Bandi 自有数据。
12. 旧非零开发数据直接重置，不建设迁移或运行时兼容层。
