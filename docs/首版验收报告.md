# 首版验收报告

> 更新日期：2026-09-10
>
> 范围：Bandi Desktop 面向 9 个内置 AI 编程工具的 Team / Agent 本地配置管理闭环
>
> 状态：自动化复验通过；真实宿主与 Windows 验证待完成

## 1. 验收目标

首版唯一产品主线为：

```text
Team → Agent → 可选 Team-scoped TaskBrief
```

完成标准：

- 每个 Agent 恰属一个 Team，Personal Team 稳定存在且不可删除；
- 长期领域快照中 TaskBrief 可选、必须属于一个 Team，且不持久化 Agent 或执行状态；
- `formal-memory-v4` 只保留 Agent 长期范围；
- 固定 `/tools` 页面分别展示九工具的本机及版本状态、单项升级预览与确认、官方安装入口、固定配置位置 reveal 与启动入口；
- Client Launch v3 在启动时临时选择 Team、active Agent 和可选同 Team TaskBrief；GUI 只打开固定应用，终端工具只打开固定终端，并返回手动复制上下文；
- Bandi 不提供旧 Host Integration 安装/卸载，不接受任意路径或扫描根，不读取宿主配置正文，不暴露通用 opener、文件 API、Shell 或进程参数；
- Factory Reset 只清理 Bandi 自有数据，不触碰宿主工具目录；
- 当前运行时无旧领域双读、投影、路径 fallback 或 command；
- Web、Rust、共享合同、Tauri E2E、真实 Chromium 和 diff 检查全部通过。

Desktop 不创建或管理可执行 Task、Session、Chat、Todo、运行日志、人员调度、执行审批或 SOP 运行流程，也不提供通用 Shell、调用方指定的 executable/argv 或凭据采集。Client Launch 仅按固定映射提交启动请求或返回手动交接上下文。

## 2. 待验证的产品行为

### Team-scoped Shell

- TeamSwitcher 始终显示 current Team；
- 切换 Team 后 Agent、TaskBrief 和 Team-scoped 长期资产同步收窄；
- Agent 栏只显示当前 Team Agent；
- compact/hidden 模式不丢失 Team 入口；
- 宽屏与窄屏无横向溢出；
- 亮暗主题切换正常；
- Dialog 支持 Escape 和焦点恢复；
- 页面无 console error 或未处理 Promise rejection。

### Team / Agent 领域

- Personal Team 确定性回退；
- Agent 单 Team 归属及不同 hydration 顺序的一致性；
- Agent 创建和导入默认归入当前 Team；
- 旧非零开发数据库不迁移；检测后要求恢复出厂并重启，不保留旧领域兼容。

### Team-scoped TaskBrief

- TaskBrief 必须属于一个 Team；
- TaskBrief 只记录目标、背景、约束和期望产出；
- TaskBrief 不持久化 Agent；
- 页面和合同均不出现进度、Todo、调度、审批、运行日志或验收状态；
- 删除 Team 时按领域约束处理其 TaskBrief，不产生执行期副作用。

### Agent 长期 Memory

- Memory 只存在 Agent 长期范围；
- 写入直接使用受限目标、baseline 复核、原子写和写后验证；
- 成功写入形成可追溯 Revision；
- `revision_pending` 和失败不伪造完整成功；
- pending recovery 与重启恢复保持一致；
- Memory 不承载聊天、Todo、运行日志或 Session 状态。

### 配置保存、历史与 Backup

- Team 共享 Rule、Skill、MCP、SOP 支持创建、staging 导入、编辑、引用反查和共享影响确认；
- 共享资产创建/导入保留 registration recovery，编辑保存保留 baseline、Revision 与 revision recovery；永久删除与跨 Team 授权不在首版；
- 稳定资产身份、kind 与 owner 校验；
- asset/container 双哈希 baseline；
- 编辑期间外部变化和三方 Diff；
- 原子写、重读验证和 ConfigRevision；
- Revision 写入失败与 pending recovery；
- 长期权限扩大的一次性 challenge；
- Backup 内容哈希、symlink、损坏内容、stale preview、恢复前安全快照与 baseline changed。

Backup 只覆盖 discovery 当前发现、用户选择且可写的受管配置文件，不替代普通保存或领域数据库，也不包含凭据和执行过程。

### 固定 `/tools` 九工具页面

必须验证：九工具均有独立详情；检测只检查固定候选，不运行工具、不扫描 PATH、不读取配置正文；官方安装按钮只打开固定 URL且不自动安装；reveal 只显示已存在的固定配置位置；所有操作只接受稳定工具 ID，不暴露通用 opener、文件 API 或 Shell。

### Client Launch v3

唯一请求语义：

```text
clientId / adapterId / terminalId / intent
teamId / agentId / taskId?
```

必须验证：

- 后端重新验证 Team、Agent 和可选 TaskBrief 的存在性与同 Team 关系；
- 启动时临时选择 Team、active Agent 和可选同 Team TaskBrief，不持久化参与关系；
- 请求不含调用方提供的路径、cwd、prompt、TaskBrief 正文、bundle ID、executable、argv、环境变量、stdin 或脚本；
- 后端只允许固定工具与 Adapter 组合；GUI 工具打开固定应用，终端工具打开用户所选固定终端，不传递 CLI 命令、prompt 或通用 argv，错配请求不触发外部动作；
- 当前可证明结果为 `application_launch_requested | manual_context_required` 与 `manual_copy`；前端拒绝把不一致组合显示为成功；
- 剪贴板失败时保留 Dialog 和手动复制入口；Bandi 不读取输出、不保存 PID、不管理 Session，请求已提交不表示工具或 CLI 已初始化、登录或任务已开始。

### 宿主目录固定边界

信任边界必须由合同、实现和自动测试共同保证：

- Bandi API 不接收任意用户路径或目录标识；
- 应用内不枚举、不选择、不提交用户目录，不读取或展示宿主配置内容；
- 配置发现只访问 Bandi 自有受管根；
- AI Tool Host 只接收稳定 `toolId` 与 `requestId`，安装候选、官方 URL 和配置位置由后端固定 catalog 解析；
- 检测不运行工具、不扫描 PATH；reveal 只显示固定配置位置，官方安装入口只打开固定 URL；二者不读取配置正文，也不暴露通用 opener、文件 API、Shell 或脚本；
- Bandi 不自动下载或安装工具、Plugin、MCPB、Skill 或其他集成；
- Factory Reset 只作用于 Bandi 自有存储；各宿主入口哨兵在重置前后保持存在且内容不变。

## 4. Tauri E2E 验收路径

首次旅程：

1. 确认 Personal Team 存在；
2. 创建 Team；
3. 创建两个同 Team Agent；
4. 创建 Team-scoped TaskBrief，并确认其中不持久化 Agent 或执行状态；
5. 编辑 Agent Instructions 和 Agent 长期 Memory；
6. 核对 UI、IPC、SQLite、AgentPackage 和 Revision 事实；
7. 从 `/tools` 启动并调用 Client Launch v3，确认返回匹配的 typed `outcome` / `contextDelivery`，且不读取输出或创建 Session；
8. 用第二个进程和相同隔离数据区恢复当前快照；
9. 用全新隔离 HOME 验证无 demo Agent。

设置与重置旅程：

1. 打开 `/tools`，确认固定展示九个工具且没有自定义工具或方案 CRUD；
2. 对九工具分别验证固定候选检测、官方安装页、固定配置位置 reveal、越权字段拒绝和 typed 状态；
3. 无损打开引导回顾；
4. 在各固定宿主入口写入隔离哨兵；
5. preview 并提交 Factory Reset；
6. 验证哨兵未变化；
7. 新进程验证 Bandi 回到初始状态，哨兵仍存在。

E2E 使用 `bundle.active: false` 时，不覆盖安装器、签名、升级或卸载。

## 5. 安全与故障场景

自动测试至少覆盖：

- 非法稳定 ID、unknown field、kind/owner 不匹配；
- 受限配置根、目标和中间节点 symlink；
- 任意路径或目录字段被合同拒绝；
- stale baseline、外部替换、revision pending；
- 过期、错配和复用的长期权限 challenge；
- 跨 Team Agent、TaskBrief 与长期资产引用关系；
- Agent 长期 Memory 的 baseline 变化、写失败与恢复；
- Backup 损坏、stale preview 与恢复前变化；
- Factory Reset 目标变化、确认错配、rename 失败回滚与启动清理；
- 未验证或错配 Client Adapter 不触发外部动作；
- 所有失败路径不伪造成功、任务或 Session 状态。

## 6. 数据与回滚结论

- AgentPackage 文件保存 Agent 配置正文；SQLite 保存 Team、可选 TaskBrief、Agent 索引、Revision 与恢复元数据；
- 普通配置和 Agent 长期 Memory 的恢复均生成新 Revision，不覆盖旧历史；
- Backup 恢复前创建当前状态安全快照；
- AgentPackage 与 SQLite 不宣称跨介质 ACID，跨介质操作通过 recovery operation 和真实 hash 恢复；
- 删除 Agent、Team、TaskBrief 或执行 Factory Reset 均不得访问或改动任意用户目录及 `~/.claude`。

## 7. 用户人工验收脚本

1. 启动 Desktop：`pnpm desktop:dev`。
2. 确认 Personal Team 存在；创建第二个 Team 并切换，验证 Agent、TaskBrief 和 Team-scoped 长期资产不串 Team。
3. 在当前 Team 创建 Agent，编辑 Instructions 并保存，确认产生真实 ConfigRevision。
4. 再次保存相同内容，确认不新增版本；外部修改受管配置文件后保存，确认出现三方 Diff 而非静默覆盖。
5. 创建 TaskBrief，确认它只属于当前 Team，且页面没有 Agent、进度、Todo、审批、日志或验收字段。
6. 直接编辑并保存 Agent 长期 Memory，确认形成新 Revision，并检查历史恢复不会覆盖旧版本。
7. 打开 `/tools` 并选择一个工具继续，确认 Team、Agent 和可选 TaskBrief 仅为本次临时选择；GUI 只打开固定应用，终端工具只打开固定终端，上下文复制后明确提示手动粘贴。
8. 在设置中创建本地 Backup，预览并恢复，确认恢复前安全快照和新 ConfigRevision。
9. 执行 Factory Reset 前在 `~/.claude` 放置哨兵，重启后确认内容不变。
10. 在宽屏与窄屏使用 Tab、Shift+Tab、Enter 和 Escape 操作 TeamSwitcher、Dialog 和 Sheet，确认焦点可见且关闭后回到合理触发点。
