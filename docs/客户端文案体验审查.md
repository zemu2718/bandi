# Bandi 客户端文案体验审查

> 审查基线：2026-09-08 当前产品契约
>
> 状态：Team / Agent / TaskBrief 当前有效文案审查
>
> 当前契约：[《产品与页面架构》](./产品与页面架构.md) · [《页面低保真线框图》](./页面低保真线框图.md)
> 方法：项目级 `product-content-strategist` Skill + 页面 × 状态 × 来源 × 文案表面交叉审查

## 1. 执行摘要

Bandi 客户端文案必须服务同一条主线：

> **选择 Team → 选择 Agent → 按需选择 TaskBrief → 准备上下文 → 回到 Claude Code**

当前内容策略的最高优先级是准确表达五项产品事实：

1. Bandi 管理 Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes 和 Pi 的长期 Agent / 配置；
2. TaskBrief 只属于 Team，不关联 Agent，也不是任务执行记录；
3. Memory 只有 Agent 长期一类，并直接通过安全保存链写入；
4. Client Launch v3 只准备上下文，不打开目录、终端或进程；
5. Bandi 应用内只查看自有配置；宿主用户目录仅允许用户显式触发的固定 allowlist 原生入口安装与目录 reveal，不接受任意路径、不扫描、不读取宿主配置内容。

一句话内容原则：

> **默认界面说用户任务；风险确认说实际影响；技术详情说证据。**

## 2. 审查范围与方法

### 2.1 已覆盖入口

- 应用 Shell、Team 切换器与配置概览；
- Agent 列表、创建、导入、详情、配置、长期 Memory 和危险区；
- Team-scoped TaskBrief 列表、详情、创建与归档；
- 资产、设置、Backup、恢复出厂；
- Client Launch v3；
- 首次使用、404、路由错误和全局通知。

### 2.2 已覆盖状态

默认、加载、空态、筛选无结果、成功、校验失败、系统失败、只读、外部变化、恢复待补记、权限边界和危险确认。

### 2.3 三问门槛

每条改写至少满足以下一项，否则保留原文：

1. 当前文案违反明确内容规则；
2. 术语、歧义、缺少条件或缺少结果会使用户困惑；
3. 文案隐藏或错误描述真实行为。

## 3. Bandi Voice Chart

| 场景 | 用户此刻需要 | 语气 | 应该这样写 | 避免 |
|---|---|---|---|---|
| 首次使用 | 明白产品价值和第一步 | 清楚、从容 | 先说“新建或导入 Agent”，再说明安全边界 | 一开始解释目录结构和内部模型 |
| 日常配置 | 快速完成查看、修改、保存 | 直接、克制 | 动词 + 对象；结果与按钮一致 | 重复产品边界、泛泛的“保存” |
| 成功反馈 | 确认结果和影响范围 | 简短、确定 | “主指令已保存” | “成功地完成了……” |
| 错误恢复 | 知道什么没完成、为何、怎么办 | 冷静、具体 | “无法保存主指令。配置已在外部变化，请重新载入后比较。” | 原始错误码、责备用户、只有“无效” |
| 外部变化 | 避免误覆盖并保留输入 | 审慎 | 说明当前配置已变化、不会自动覆盖、下一步 | 只说“基线冲突” |
| 删除/恢复 | 理解范围、不可逆性和保留项 | 严肃、无修辞 | 明列只处理 Bandi 自有数据，不处理用户目录 | 为了简短省略事实；“确定吗？” |
| Claude Code 交接 | 知道上下文准备到哪一步 | 务实 | “上下文已准备” | 暗示已打开目录、终端、任务或 Session |
| 技术详情 | 为排障提供证据 | 精确、可复制 | 错误码、ID、哈希放可展开区域 | 把诊断详情作为主文案 |

Bandi 的稳定 Voice：**可靠、克制、清楚、安全审慎、不越权**。Tone 随风险升高而更直接，但不生硬或责备用户。

## 4. 术语分层

| 层级 | 术语 | 使用规则 |
|---|---|---|
| 可直接使用 | Team、Agent、TaskBrief、Claude Code、MCP、SOP、Skill | 目标用户日常使用；保持大小写和产品内一致 |
| 默认用户层 | Agent 配置、配置版本、记忆修改建议、当前配置、外部修改、本地备份、上下文 | 页面标题、按钮、空态、通知和主错误优先使用 |
| 仅技术详情 | AgentPackage、ConfigRevision、MemoryRevision、baseline、哈希、schema、requestId、诊断 code | 只在原始配置、开发者证据和可展开技术详情中出现 |
| 禁止作为当前产品概念 | 目录型业务上下文、Agent 与其他业务对象的绑定、多范围Agent 长期 Memory | 不出现在导航、字段、帮助、确认、空态、状态或验收文案中 |

展示层应复用明确的 label map。错误按稳定 code 或结果类型映射，不对任意文本做全文替换，也不把未知协议值直接显示在默认用户层。

## 6. 动态与后端文案治理

### 6.1 四层错误模型

1. **用户动作未完成**：`无法保存主指令`；
2. **可理解原因**：`配置已在外部修改`；
3. **下一步**：`重新载入后比较你的修改`；
4. **技术详情**：错误码、ID、阶段和可复制证据。

示例：

```text
无法保存主指令
配置已在外部修改。重新载入后比较你的修改；Bandi 不会自动覆盖当前版本。

技术详情
BASELINE_CHANGED · asset=…
```

技术详情不得包含或暗示 Bandi 已接受、扫描或操作用户目录。

### 6.2 归属规则

| 内容 | 最佳归属 | 原因 |
|---|---|---|
| 稳定名词、状态、资产类型 | 前端显式映射 | 多页面一致、可测试 |
| 动作是否完成、行为事实、影响清单 | Rust/Tauri 结构化结果 | 后端最了解真实行为 |
| 面向页面的主错误和下一步 | 前端按结果类型映射 | 需要结合当前用户动作和页面入口 |
| 错误码、ID、哈希、阶段 | 折叠技术详情 | 用于诊断，不是主任务 |

不要把后端错误改成更口语的字符串后继续透传。优先返回稳定 code/typed result，由前端按动作提供主文案。

## 7. 高风险流程专项

### 7.1 永久删除 Agent

必须保留以下事实：

- 删除哪些 Bandi 自有数据；
- 独立 Backup 是否仍可能保留副本；
- 操作是否不可逆；
- 预览会过期，提交时会再次检查；
- Bandi 不处理任意用户目录或其中的文件。

### 7.2 Backup 恢复

恢复前重新检查当前 Bandi 数据状态，必要时先保存当前状态。不得将 Backup 描述为用户文件备份，也不得暗示恢复会读取、比较或修改用户目录。

### 7.3 恢复出厂

默认清单按用户能理解的数据类别表达：Bandi 数据库、受管 Agent 配置、版本、Backup 和 UI 偏好。完整技术目标可在技术详情中展开。成功后要求重启，当前窗口不应继续编辑。

检测到旧非零开发数据时，提示“检测到旧版开发数据。请恢复出厂并重新启动 Bandi。”不得使用“升级数据”或“迁移数据”措辞。

### 7.4 外部变化

统一使用：

```text
当前配置已在外部修改
Bandi 不会自动覆盖。重新载入后比较当前版本、原始内容和你的修改。
```

不要只说“基线变化”；重新载入会丢草稿时必须说明。

### 7.5 长期权限与执行期批准

统一使用：“Team 归属和 Agent 长期权限不会批准当前 Session 的工具调用；执行期批准只在 Claude Code 中完成。”

## 8. Client Launch v3 内容契约

### 请求前

- 标题：`在 Claude Code 中继续`；
- 字段：`Team`、`Agent`、`任务简报（可选）`；
- 主操作：`准备上下文`；
- 帮助：`Bandi 只准备上下文，不会打开终端或启动 Claude Code。`

### 成功

```text
上下文已准备
请在 Claude Code 中继续。Bandi 不会跟踪后续 Session。
```

### 失败

```text
无法准备上下文
所选内容已变化。重新选择后再试。
```

不得出现路径、目录、cwd、终端、命令、进程、PID、“已启动”“已打开”或“已连接”等状态。

## 9. 已审查并建议保留

以下模式符合三问门槛，不建议为统一风格而改写：

- “页面不存在。请检查链接是否正确，或返回配置概览。”——状态、恢复动作和按钮一致；
- “页面暂时无法显示……返回原页面确认修改是否已保存。”——对潜在未保存状态保持审慎；
- 离开编辑页时明确“继续编辑 / 放弃修改”，并说明未保存内容不会写入；
- Agent 导入明确只读取用户选择的单文件、创建 Bandi 受管副本并保持来源只读；
- 长期权限扩大明确说明不会批准当前 Session 的工具调用；
- TaskBrief 明确说明归档不代表执行完成。

## 10. 分批落地顺序

### 批次 A：正确性与风险

- 统一删除、Backup 恢复和恢复出厂的 Bandi 自有数据边界；
- 清除所有暗示接受、登记、打开、扫描或操作用户目录的文案；
- Client Launch v3 改为 context-only 结果；
- 删除部分完成状态按真实阶段呈现。

### 批次 B：主流程术语

- 主线统一为 Team、Agent、可选 TaskBrief；
- TaskBrief 去除 Agent 和执行关系；
- Memory 统一为 Agent 长期并直接安全保存；
- 内部协议词下沉到技术详情。

### 批次 C：统一错误呈现

- 按动作与结果类型建立最小显式映射；
- 原始 message、code、ID 进入技术详情；
- 字段错误邻近输入并用 ARIA 关联；
- 全局 notice 不再统一使用等宽字体。

### 批次 D：信息层级与空态

- 区分无数据与筛选无结果；
- 空态先确认系统状态，再提供一个真实主操作；
- 普通页面不重复完整安全声明，高风险动作必须保留完整事实。

## 11. 验收清单

- [ ] 默认页面只使用 Team、Agent、可选 TaskBrief 组成产品主线。
- [ ] TaskBrief 只属于 Team，不显示 Agent、负责人或执行状态。
- [ ] Memory 只有 Agent 长期一类，并直接通过安全保存链写入。
- [ ] Client Launch v3 只显示上下文准备状态，不出现目录、终端或进程语义。
- [ ] 产品文案不暗示 Bandi 接受、访问、扫描、修改或删除任意用户目录。
- [ ] 删除与恢复明确只处理 Bandi 自有数据。
- [ ] 每个失败状态说明未完成的用户动作；可安全给出时包含下一步。
- [ ] 原始 Rust/Tauri 错误不直接作为主文案。
- [ ] 空态先确认系统状态，再提供一个真实可用的主行动。
- [ ] 每个字段错误与字段名称一致，并由 ARIA 关联。
- [ ] 只对 ID、哈希和代码使用等宽字体。
- [ ] 更新受影响测试后，通过 Web lint、typecheck、test、build 和相关 Rust 测试。
- [ ] 用真实 Chromium 检查亮暗主题、宽窄屏、键盘焦点、控制台错误和横向溢出。

## 12. 结论

Bandi 不需要全站文案平台。最小有效方案是：保留页面附近的具体说明，复用现有展示映射，按结果类型呈现错误，并把协议证据放入技术详情。

最终目标是让用户无需理解内部模型，也能放心完成：

> **选择 Team → 选择 Agent → 按需选择 TaskBrief → 准备上下文 → 回到 Claude Code**
