# 本地服务与前端联调契约

> 文档版本：v4.0
> 更新日期：2026-09-09
> 状态：当前有效契约（长期领域 v4）
> 关联文档：[《产品与页面架构》](./产品与页面架构.md) · [《技术架构》](./技术架构.md) · [《首版能力矩阵》](./首版能力矩阵.md)

## 1. 范围

本文冻结 Bandi Desktop 前端与 Rust Local Service 的当前跨进程语义：9 个内置 AI 编程工具（Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes、Pi）的 Team、长期 Agent、可选 Team-scoped TaskBrief、长期配置资产、Agent 长期 Memory、本地 Backup/Restore、Host Integration 和 Client Launch v3。核心 DTO 在本文直接列出；可执行 JSON Schema 与跨语言 fixture 位于 `packages/contracts/`。名称、字段、必填性和枚举值不得由 Rust 或 TypeScript 单方面改变。

Local Service 内部名称不是 wire API。传输可使用 Tauri Command 或受限 localhost API，但不得改变本文 DTO 的业务语义。

当前运行时只维护长期领域 v4。旧非零开发数据库不迁移，服务返回 `LEGACY_DATABASE_RESET_REQUIRED: 检测到旧版开发数据库；请重置 Bandi`。重置和删除操作只处理 Bandi 自有数据；Bandi 不接受、访问、扫描、修改或删除任意用户目录。

TaskBrief（界面称“需求”）属于一个 Team，只保存轻量需求上下文，不持久化 Agent，也不产生执行状态。

本契约不包含：

- 可执行 Task、WorkflowRun、Assignment、任务 Handoff 或执行期 Approval；
- Session 创建、attach、停止、恢复或跟踪；
- 聊天、Todo、工具调用、日志、Usage 或 Agent View 镜像；
- Desktop SOP 执行器；
- 通用进程参数、Provider、Model、账户、Quota 或任意 Shell API；
- Plugin / MCP 直接写 SQLite、AgentPackage 或 Agent 长期 Memory；
- 首轮远程 Git、多设备同步或自动冲突合并协议。

## 2. 通用序列化规则

```ts
type Id = string
type Timestamp = string // RFC 3339 UTC，例如 2026-08-31T10:42:00Z
type ContentHash = `sha256:${string}`
type RelativeAssetPath = string
type RootKind = 'managed' | 'bandi'
type OfficialScope = 'managed' | 'bandi'
type CapabilityStatus = 'supported' | 'degraded' | 'unavailable' | 'not_checked'

type CapabilityFactDto = {
  status: CapabilityStatus
  reason: string
  evidence: string[]
  remediation: string[]
}
```

- JSON 字段使用 `camelCase`，枚举值使用稳定 ASCII `snake_case`。
- Rust DTO 必须显式使用与 wire 形状等价的 Serde 标注：结构体字段采用 `#[serde(rename_all = "camelCase", deny_unknown_fields)]`；以 `kind` 判别的联合采用 `#[serde(tag = "kind", rename_all = "snake_case")]`，各分支 payload 与本文扁平 JSON 一致。不能依赖 Rust 默认枚举编码或默认忽略未知字段。
- 本文冻结的请求、结果、事件和其嵌套业务 DTO 均拒绝未知字段；TypeScript runtime codec / JSON Schema 与 Rust `deny_unknown_fields` 必须使用同一 fixture 验证，防止 `SaveConfigRequest` 被额外路径或未冻结 kind 扩展。
- 持久化对象 ID 由 Local Service 生成且对调用方不透明；Client Launch v3 不接受 `requestId`，其他带 `requestId` 的调用由调用方生成，仅用于幂等和关联。
- 时间统一传 RFC 3339 UTC，不传“刚刚”“昨天”等展示文本。
- 内容哈希必须携带算法前缀。
- 写操作以稳定 `assetId` 定位。AgentPackage 内路径使用不含 `..` 的规范相对路径；Local Service 不接受或返回用户路径。
- 字段缺失表示“未提供”；`null` 仅用于 Schema 明确允许的清除语义；空字符串是实际值，不与前两者混用。
- 前端不得根据中文文案判断业务分支，只判断 `kind`、`code` 等稳定字段。
- secret 必须在 Local Service 内脱敏；前端 DTO 不传 secret 原文，不能用 CSS 隐藏代替脱敏。
- 所有可用性或接入能力必须使用 `CapabilityFactDto`；`reason` 解释结论，`evidence` 只列可验证事实，`remediation` 只列用户可执行的补救动作。`not_checked` 不得被前端展示为可用，`degraded` 必须说明仍可完成的降级路径，`unavailable` 不得生成或执行猜测性命令。

Bandi 应用内不扫描或导入宿主工具中的 Agent 文件；配置发现只覆盖 Bandi 受管 AgentPackage。应用内不接受任意路径，不枚举、不扫描、不读取宿主配置内容；用户显式触发的固定 allowlist Host Integration 由第 10 节独立约束。

长期领域快照固定为：

```ts
type LongTermDomainSnapshotV4 = {
  schemaVersion: 4
  teams: TeamDtoV4[]
  taskBriefs: TaskBriefDtoV4[]
}
```

Desktop 使用 `load_long_term_domain_snapshot_v4` 加载长期领域快照。Team 的写入与删除入口为 `save_team_v4` / `remove_team_v4`，TaskBrief 的写入与删除入口为 `save_task_brief_v4` / `remove_task_brief_v4`；Agent 则通过受管 Agent 专用命令保存。稳定 ID `team-personal` 的 Personal Team 始终存在且不可删除。`FullAgent.teamId` 是 Agent 单 Team 归属的唯一事实源；`Team.memberAgentIds` 由后端聚合或前端派生。v4 DTO 严格拒绝未知字段；旧非零开发数据库只识别并要求恢复出厂，不从旧字段投影当前领域事实。

AgentPackage 文件与 SQLite 不承诺单一 ACID 事务。受管 Agent 创建和身份编辑通过 `commit_managed_agent_creation` / `commit_managed_agent_identity` 提交，并在首次文件写入前持久化 recovery operation。身份提交只处理 Agent 自身长期身份及 Team 归属。`continue_agent_recovery` 只继续未完成阶段；当前文件 hash 不匹配时进入 `blocked`，不得覆盖外部变化。

受管 Agent 永久删除使用 `preview_managed_agent_deletion` / `commit_managed_agent_deletion` 两阶段合同，只接受稳定 ID、服务签发的预览引用和精确确认文本。Preview 必须结构化展示共享引用、Agent 长期 Memory、Revision 和 Backup 影响；存在 blocker 时不得提交。删除 Agent 不连带删除 Team、共享资产或独立 Backup，且不得访问任意用户目录。

发现只读取 Bandi 受管根，不导入、不安装、不改写受管范围外文件。历史外部 Agent 引用不进入配置发现。`SourceContainerDto` 表示物理文件或目录，`SourceAssetSummaryDto` 表示其中逻辑 fragment。当前配置资产 kind 固定为 Agent 根级长期配置；不发现或投影其他范围的配置。

`SharedAssetNodeDto.id` 是共享资产逻辑稳定 ID，不能与配置资产 ID 混用。共享资产按 Team 作用域解析，不建立跨 Team 授权模型。共享根不存在时目标为 `unresolved`，根可读取但目标不存在时为 `dangling`。当前共享资产能力只读，不包含创建、编辑、删除或安装事务。

## 4. 基础诊断

```ts
type Diagnostic = {
  code: string
  severity: 'error' | 'warning' | 'info'
  message: string
  field?: string
  path?: RelativeAssetPath
  range?: {
    startLine: number
    startColumn: number
    endLine: number
    endColumn: number
  }
  remediation?: string
}
```

`code` 是行为判断依据，`message` 是可直接展示的本地化文本。前端必须能通用展示未知 `code`，不能因未知诊断而丢失错误信息。字段级错误尽量提供 `field`，原文错误尽量提供 `path` 和 `range`。当前稳定 code family 已覆盖 package legacy/future/unverified、manifest 无效、Hook/Command/OutputProfile kind 或引用错误、共享资产及引用异常、Plugin 不完整/不兼容和 parameter binding 无效；前端不得从中文 message 反推分支。新增 code 必须保持未知 code 可展示并补对应合同或领域测试。

## 5. 普通配置保存

### 5.1 请求

现有前端 `apps/web/src/agent-config-model.ts` 的 `AgentConfigPayload` 可继续作为页面内判别联合思路，但不能直接作为 wire DTO。跨进程请求必须包含目标资产和编辑基线。

```ts

  value: string

  value: string
}

type SkillsConfigChange = {
  kind: 'skills'
  value: string
}

type McpConfigChange = {
  kind: 'mcp'
  value: string
}

type PermissionsConfigChange = {
  kind: 'permissions'
  value: string
}

type SopConfigChange = {
  kind: 'sop'
  value: string
}

type HooksConfigChange = {

  value: string

type SaveConfigOwner = {
  agentId: Id
}

  requestId: Id
  assetId: Id

  expectedBaseline: BaselineRefDto
  baseContent: string
  confirmationRef?: Id

```

当前保存切片只允许明确列出的 `change.kind`。Instructions 与各 YAML 配置的 `value` 是对应 canonical 文件的完整规范文本。引用保存只维护长期配置关系，不表示资产已安装、已连接、被宿主加载或当前 Session 已应用；SOP 保存不创建任务、不选择参与 Agent、不推进流程，也不管理 Session。Hooks 与 Commands 保存只维护定义引用和非敏感参数，不接受脚本文本、Shell、cwd、环境变量、executable、argv、stdin 或执行期输入，不触发执行。


`baseContent` 必须原样携带本次 `LoadEditorResult.canonicalContent`。Local Service 确认资产身份、owner、change kind、可写性和解析状态，并执行双哈希基线复核、受限原子写入、重读验证和 ConfigRevision 记录。AgentPackage schema 由 Local Service 基于已读取事实判断；不可验证或不受支持的包保持只读。

配置方案、工具登记、备份、网络代理和 Plugin 安装不属于普通保存切片。上下文交接只使用第 10 节 Client Launch v3，不映射 Gateway、Provider、凭据或宿主工具真实配置。

### 5.2 结果

```ts
type SaveConfigResult =
  | Saved
  | Unchanged
  | BaselineChanged
  | ConfirmationRequired
  | ValidationFailed
  | SaveFailed

type WriteReceiptDto = {
  id: Id
  containerId: Id
  previousContainerHash: ContentHash
  writtenContainerHash: ContentHash
  verifiedAt: Timestamp
  atomicReplace: boolean
}

type Saved = {
  kind: 'saved'
  requestId: Id
  asset: SourceAssetSummaryDto
  revision: ConfigRevisionDto
  writeReceipt: WriteReceiptDto
}

type Unchanged = {
  kind: 'unchanged'
  requestId: Id
  asset: SourceAssetSummaryDto
}

type ValidationFailed = {
  kind: 'validation_failed'
  requestId: Id
  diagnostics: Diagnostic[]
}

type SaveFailed = {
  kind: 'save_failed'
  requestId: Id
  diagnostics: Diagnostic[]
  retryable: boolean
  fileState: 'unchanged' | 'write_not_verified' | 'verified_written_revision_pending'
  recoveryRef?: Id
}
```

只有写入、重读验证和 ConfigRevision 记录都成功，才能返回 `saved`。内容无变化返回 `unchanged`，不生成 revision。前端只有收到 `saved` 或 `unchanged` 才更新 canonical 状态并退出编辑；其余结果必须保留 draft。

前端只调用一次类型化保存请求。Local Service 内部的目标解析、基线加载、校验、基线复核、原子写入、重读验证和 revision 记录不得扩张为前端逐步调用的向导或事件状态机。

## 6. 外部基线变化

```ts
type ConfigSide = {
  content: string
  assetContentHash: ContentHash
  containerContentHash: ContentHash
  redacted: boolean
  revisionId?: Id
}

type BaselineChanged = {
  kind: 'baseline_changed'
  requestId: Id
  assetId: Id
  containerId: Id
  fragment?: string
  locator: AssetLocatorDto
  base: ConfigSide
  current: ConfigSide
  proposed: ConfigSide
  diagnostics: Diagnostic[]
}
```

- `base` 是前端开始编辑时的内容，`current` 是 Local Service 重新读取的当前内容，`proposed` 是用户待保存内容。
- Local Service 不接受通用 `force` 绕过基线检查。
- 用户放弃、复制自己的编辑或基于 current 重新应用后，前端必须重新加载服务签发的 `baselineRef` 再提交；不能只替换一个 hash。
- 只有无法安全自动合并的同字段或同文本区域变化才称为配置文件冲突；普通外部变化先展示三方内容。

## 7. 当前操作确认

```ts
type ConfirmationChallenge = {
  id: Id
  assetId: Id
  proposedContentHash: ContentHash
  expiresAt: Timestamp
  reason: string
}

type ConfirmationRequired = {
  kind: 'confirmation_required'
  requestId: Id
  challenge: ConfirmationChallenge
  diagnostics: Diagnostic[]
}
```

Permissions challenge 绑定资产、待写内容哈希、签发时基线哈希（仅服务端持久化）和有效期，当前有效期为 10 分钟。确认后前端使用同一业务请求并附带 `confirmationRef`；Local Service 必须重新校验 challenge 未过期、资产、内容哈希和当前基线仍匹配。challenge 在成功校验时一次性消费，不能复用；若后续文件写入失败，用户须重新发起保存并取得新的 challenge。

文件权限扩大按严格等级比较：`未授予 < 只读当前工作区 < 仅当前工作区 < 任意目录`。当前页面只编辑 `files`；为避免无法证明安全的隐式扩权，`commands / network / delegation` 任意变化均保守视为扩大并要求确认。收紧不需要确认，且携带 `confirmationRef` 会被拒绝。成功扩权生成的 `ConfigRevisionDto.confirmationRefs` 必须记录 challenge ID。恢复历史版本复用相同权限比较：恢复到更宽边界先返回 `confirmation_required`，确认后才恢复为新版本。

这是当前长期配置操作的短期确认引用，不是 Approval、Task 或可复用权限；页面输入 Agent 名称与勾选理解后果只是独立 UI 确认步骤，不是跨进程授权凭据。Claude Code 中某次工具调用的一次性授权不进入本契约。

wire DTO 不携带 Web Mock 的 `payload: unknown`、`demo-fixture` / `memory-only` 证据、secret 原文或相对时间。历史内容通过 `read_config_revision_content` 按需查询，不在列表 DTO 中复制大文本；服务必须校验 metadata、正文文件身份和 `assetContentHash`。

Instructions 历史恢复使用独立请求，不复用通用 force：

```ts
type RestoreConfigRevisionRequest = {
  requestId: Id
  assetId: Id
  revisionId: Id
  expectedBaseline: BaselineRefDto
  baseContent: string
  confirmed: boolean
  confirmationRef?: Id
}

type RecoverConfigRevisionRequest = {
  requestId: Id
  assetId: Id
  recoveryRef: Id
}
```

`RestoreConfigRevisionRequest` 只允许恢复属于同一 `assetId` 的历史正文；`confirmed` 必须为 true，且服务必须按当前 `expectedBaseline + baseContent` 重新复核磁盘状态。Permissions 恢复若扩大长期边界，第一次调用返回 `confirmation_required`，前端核对影响后以同一恢复请求附带 `confirmationRef` 重试。成功恢复通过正常安全写入链生成新的 `ConfigRevisionDto` 并写入 `restoredFromRevisionId`，不得修改旧历史。

当普通保存已经写后验证成功、但 revision 记录失败时，服务返回 `fileState: 'verified_written_revision_pending'` 与 `recoveryRef`。`RecoverConfigRevisionRequest` 只补记当前磁盘中已重新读取并验证的正文，不再次覆盖配置文件；若补记仍失败，继续返回同一 `recoveryRef`，不得伪报保存成功。


## 9. Local Service 事件

```ts
type LocalServiceEvent =
  | ConfigInvalidatedEvent
  | OperationProgressEvent

type ConfigInvalidatedEvent = {
  kind: 'config_invalidated'
  eventId: Id
  occurredAt: Timestamp
  assetIds: Id[]
  reason: 'external_change' | 'discovery_changed' | 'parser_changed'
}

type OperationProgressEvent = {
  kind: 'operation_progress'
  eventId: Id
  occurredAt: Timestamp
  operationId: Id
  operationKind: 'discovery' | 'backup' | 'restore'
  phase: string
  completed: number
  total?: number
  message?: string
}
```

- 配置失效事件只通知前端重新查询，不携带未经重读验证的完整事实。
- 进度事件只用于明显长操作；普通单文件保存直接返回结果。
- `phase` 只用于显示，不驱动业务状态机。操作最终结果必须由对应请求返回或查询取得。
- 不发布 Session、Agent 运行、任务、审批、工具调用、Todo 或日志事件。

本地 Backup/Restore 已通过独立 command 返回最终结果；当前尚未发布 `operation_progress` 事件。事件枚举不能作为快照已创建或恢复成功的证据。Backup wire 以 `packages/contracts/schemas/backup-local.schema.json` 和对应 fixture 为准。

## 9.1 Agent 长期 Memory 直接保存

```ts
type SaveMemoryRequest = {
  requestId: Id
  spaceId: Id
  agentId: Id
  content: string
  contentHash: ContentHash
  expectedBaseline: BaselineRefDto
}
```

Local Service 根据 `agentId` 与 `spaceId` 重取受限目标，执行 baseline 复核、内容哈希校验、原子写入、重读验证、write receipt、MemoryRevision 与 recovery。结果固定为 `saved`、`baseline_changed`、`revision_pending`、`validation_failed` 或 `save_failed`；写入成功但 Revision 待补记时返回 `revision_pending`。

## 10. Host Integration

Host Integration 与 Client Launch v3、工具方案 CRUD 完全独立，只能由用户在对应界面显式触发：

```ts
type BuiltInClientId =
  | 'claude_code'
  | 'claude_desktop'
  | 'codex'
  | 'gemini'
  | 'grok'
  | 'opencode'
  | 'openclaw'
  | 'hermes'
  | 'pi'

type HostIntegrationAction = 'install' | 'reveal'

type HostIntegrationRequest = {
  clientId: BuiltInClientId
  action: HostIntegrationAction
}

type HostIntegrationResult = {
  clientId: BuiltInClientId
  action: HostIntegrationAction
  capability: CapabilityFactDto
  outcome: 'completed' | 'official_ui_required' | 'not_checked'
}
```

固定入口：

| `clientId` | 固定入口 | 未经 smoke 的运行态 |
| --- | --- | --- |
| `claude_code` | plugin | `not_checked` |
| `claude_desktop` | MCPB；官方 UI 安装 | `degraded` |
| `codex` | `~/.agents/skills` | `not_checked` |
| `gemini` | `~/.gemini/extensions` | `not_checked` |
| `grok` | `~/.grok/skills` | `not_checked` |
| `opencode` | `~/.config/opencode/skills` | `not_checked` |
| `openclaw` | `~/.openclaw/skills` | `not_checked` |
| `hermes` | `~/.hermes/skills` | `not_checked` |
| `pi` | `~/.pi/agent/skills` | `not_checked` |

严格规则：

- 请求只允许上列稳定枚举，不接受路径、cwd、URL、bundle ID、executable、argv、Shell、AppleScript、环境变量、stdin 或脚本；后端从编译期固定 registry 解析目标。
- `install` 只写对应固定入口；`reveal` 只调用原生文件管理器显示对应固定目录。二者均不得读取、解析或返回宿主配置内容，不得暴露通用 opener、文件 API、Shell 或进程接口。
- Claude Desktop 不直接写宿主目录，只返回 `official_ui_required` 和官方 MCPB UI 安装补救说明，能力为 `degraded`。
- 工具方案创建、保存或选择不得触发安装或 reveal。reveal 完成不表示已安装、已加载或可运行。
- 未执行真实 smoke 时运行态必须为 `not_checked`；仅部分链路可用时为 `degraded` 并提供 remediation。入口已知、文件已复制或 UI 已打开均不能单独证明运行可用。

## 11. Client Launch v3

`request_client_launch_v3` 是唯一上下文准备入口。v3 是 context-only：只验证并准备 Team、Agent 与可选 TaskBrief 上下文，不调用客户端、终端或外部进程，也不调用 Host Integration。

```ts
type RequestClientLaunchV3 = {
  clientId: BuiltInClientId
  adapterId: ClientAdapterId
  terminalId: TerminalId
  intent: 'start_with_context'
  teamId: Id
  agentId: Id
  taskId?: Id
}

type ClientLaunchResultV3 = RequestClientLaunchV3 & {
  capability: CapabilityFactDto
  outcome: 'context_prepared'
}
```

严格规则：

- Rust 与 TypeScript 均拒绝未知字段；请求顶层只允许上列字段，不接受 `requestId`、路径、目录 ID 或命令。`intent` 固定为 `start_with_context`；`terminalId` 仅保留适配器上下文标识，不授权调用终端。
- `teamId` 与 `agentId` 必填；服务端重新校验 Team 成员关系及 Agent 生命周期。`taskId` 只允许指向同 Team 的轻量 TaskBrief，不表示存在可执行 Task。
- Bandi 不接受、访问或扫描用户目录，不解析 cwd，不调用客户端、终端或外部进程，不执行命令，不读取输出、不保存 PID、不跟踪 Session。
- 结果不返回路径、命令或 TaskBrief 正文；`context_prepared` 仅表示上下文已准备完成，不表示客户端、任务或 Session 已开始。

## 11. 前端状态处理

真实联调后的前端状态流固定为：

```text
页面 draft
→ SaveConfigRequest
→ saved / unchanged：更新 canonical，退出编辑
→ baseline_changed：保留 draft，展示 base/current/proposed
→ confirmation_required：保留 draft，确认后带 confirmationRef 重试
→ validation_failed：保留 draft，定位字段或文件诊断
→ save_failed：保留 draft，展示失败和是否可重试
```

不得把当前 `apps/web/src/state.tsx` 的整个 `State`、`Action` 或同步 reducer 直接变成共享协议。页面状态、对话框开关、Toast 和严格白名单的本机 `UiPreferences` 仍是前端实现细节。主题、强调色、字体、字号、密度、主菜单布局、工作台辅助名称和背景不得通过 `SaveConfigRequest` 写入 Local Service，也不生成 ConfigRevision 或 Local Service 事件。固定槽位的 Logo / 背景图片命令仅是 Tauri 桌面壳本机能力，不是业务 DTO。

### 11.1 受管 Agent 头像窄契约

首版头像只属于 Bandi Desktop 受管 AgentPackage：根目录固定保存 `avatar.png`，`agent.yaml` 仅以可选 `avatarPath: "avatar.png"` 引用。创建命令一次接收稳定 `agentId`、完整 canonical Agent、待写配置文件和可选 PNG；后端在同父目录 staging 中全部写完后再提交。身份编辑先调用 `load_managed_agent_identity`，由服务返回稳定 identity `assetId / containerId`、真实 `canonicalContent`、locator 和双 SHA-256 `baselineRef`。身份保存命令一次接收 `requestId`、完整 canonical Agent、完整 identity manifest、服务签发的 `expectedBaseline`、原样 `baseContent`，以及 `keep | replace | remove` 头像变更；前端不提交目标目录、原文件名或任意路径。

身份保存与 Instructions 使用相同结果语义：`saved / unchanged / baseline_changed / validation_failed / save_failed`。`saved` 必须在受限原子写入、写后重读验证和 ConfigRevision（正文只记录完整 `agent.yaml`，不记录头像字节）成功后返回；revision 失败返回 `verified_written_revision_pending`。编辑期间外部变化必须返回真实 `base/current/proposed`，不提供通用 force。manifest、头像或 canonical 索引任一步写失败时必须恢复原 manifest、头像和索引记录。

头像仅接受 PNG 签名且最大 5 MiB；读取失败或缺少引用时 UI 回退姓名首字符。Desktop 启动通过只读扫描恢复受管 Agent canonical 状态。纯 Web、`external-reference`、legacy、future 和 unverified 包不得调用写命令，也不得把页面内存操作描述成磁盘保存。

## 12. 首轮联调场景矩阵

| 场景 | 请求 / 事件 | 期望结果 | 前端行为 |
| --- | --- | --- | --- |
| 配置发现 | Bandi 受管 AgentPackage | containers + assets + diagnostics | 不接受用户路径，不读取受管范围外文件 |
| TaskBrief 保存 | Team | TaskBrief 已保存 | 不持久化 Agent 或执行状态 |
| 加载编辑器 | 可编辑 assetId | canonicalContent + 双 hash baselineRef | secret 已脱敏，保存沿用 baselineRef |
| 正常保存 | 正确 owner、assetId、baselineRef 和合法 change | `saved` + revision + writeReceipt | 更新 canonical，退出编辑，显示目标文件和版本 |
| 内容未变化 | change 与当前语义一致 | `unchanged` | 更新 canonical，退出编辑，不显示新版本 |
| 字段或格式错误 | 格式不符合合同 | `validation_failed` | 保留 draft，在字段或文件位置展示诊断 |
| 编辑期间被外部修改 | expected hash 与当前不同 | `baseline_changed` + base/current/proposed | 保留 draft，禁止静默覆盖 |
| 扩大长期权限 | 新权限超出当前边界 | `confirmation_required` | 展示前后边界和后果；确认后重试 |
| 写入或写后验证失败 | 文件系统、解析或 revision 失败 | `save_failed` + fileState | 保留 draft；若 revision 待恢复，明确显示恢复状态 |
| 保存 Agent 长期 Memory | `SaveMemoryRequest` + baseline | `saved` / `baseline_changed` / `revision_pending` / `validation_failed` / `save_failed` | 直接执行安全写入并生成 Revision |
| AI 工具上下文准备 | `RequestClientLaunchV3` + Team/active Agent + 可选同 Team TaskBrief | capability + `context_prepared`；校验失败返回命令错误 | 只准备上下文；不调用客户端、终端或外部进程，不显示 Session 或执行状态 |
| 工具方案管理 | load/create/copy/save/select/delete plan；save/delete custom tool | Desktop 返回完整 canonical snapshot 与新 revision | 不乐观更新；自定义工具不自动获得外部执行能力；纯 Web 保持内存演示 |
| 本地配置文件快照 | Desktop 类型化 create/list/preview/restore；纯 Web 演示 | Desktop 返回真实快照、预览和逐项恢复结果 | 只保护明确选择的受管配置文件，不宣称完整 Bandi 备份 |
| 重置 Bandi | preview(requestId) → commit(requestId, previewRef, confirmationText) → `restart_after_factory_reset()` | 固定目标隔离成功并返回 `requiresRestart: true`；当前进程与 marker 复核后请求当前应用重启 | 提交后全局终止编辑；不接受路径、命令或进程参数；目标变化、过期或 marker 无效时拒绝；不接受或触碰任意用户目录 |
| 永久删除受管 Agent | current 受管 Agent → preview → 精确确认 → commit | 无 blocker 时删除 AgentPackage、其 revision 和派生索引；共享资产、Team 与独立 Backup 保留 | 完整展示共享引用、Agent 长期 Memory、Revision 与 Backup 影响；blocker、过期或目标变化时禁止提交 |
| 永久删除清理待恢复 | commit 已完成 SQLite 清理，但隔离目录或 revision 文件清理失败 | `database_committed` recovery operation，live Agent 不再出现 | 如实提示清理待继续，不自动重试破坏性操作，可从待处理项调用 recovery |
| 修改个性化 | `UiPreferences` 与固定 Logo / 背景槽位 | 不调用 Local Service；仅本机 UI 存储与 Tauri 窄命令 | 不影响 Agent、配置版本、备份或 RuntimeProjection |

## 13. 契约冻结清单

当前冻结以下跨进程类型：

1. `DiscoveryRequest`、`DiscoveryResult`；
2. `LoadEditorRequest`、`LoadEditorResult`；
3. Agent 根级全配置族 change 的 `SaveConfigRequest` 及 `SaveConfigResult` 全部分支；
4. `BaselineRefDto`、`Diagnostic`、`ConfigRevisionDto`；
5. `LocalServiceEvent`；
6. `CapabilityStatus`、`CapabilityFactDto`；
7. `SharedAssetNodeDto`、`AssetReferenceDto` 与引用状态；
8. `LongTermDomainSnapshotV4`、Agent 长期 Memory 与本地 Backup/Restore；
9. `HostIntegrationRequest`、`HostIntegrationResult`、固定九工具 registry 与 `install | reveal`；
10. `RequestClientLaunchV3`、`ClientLaunchResultV3` 与固定的 `context_prepared` 成功结果。

“冻结”表示 Rust、TypeScript、fixture 和合同测试必须共享同一字段与枚举；实现不得用自由字符串、`unknown`、额外 envelope 或兼容别名替代。当前未冻结的内部服务名、实时文件事件、Plugin/Skill 安装事务、远程 Git、终端安装探测、共享资产写事务不得借现有 DTO 进入公开跨进程边界。

## 14. 后续 DTO 切片冻结门槛

任何其他 DTO 进入实现前，必须先在本文增加一个独立、可验收的竖切片，并同时完成：

- 明确页面入口与单一用户结果；
- 记录当前事实、目标事实和后端责任；
- 冻结请求、结果、错误/诊断和事件；
- 指定能力状态及 `reason/evidence/remediation` 来源；
- 提供 Rust ↔ TypeScript 序列化合同 fixture；
- 覆盖成功、未检查、降级、不可用、校验失败和越权输入；
- 更新[《首版能力矩阵》](./首版能力矩阵.md)中的证据、测试与缺口。

未满足上述条件时，保持页面内存演示、只读或不可用，不得通过扩大通用 DTO、加入任意 `payload` 或复用相近命令抢先施工。

## 15. 契约变更规则

当前版本自 2026-09-08 起以 Client Launch v3 作为唯一上下文准备合同。它只接受 Team、Agent 与可选的同 Team TaskBrief 上下文，不接受路径，也不调用客户端、终端或外部进程。

- 新增可选字段必须同步 Rust、TypeScript、Schema、fixture 和测试；新增联合分支必须同步前端穷尽检查。
- 修改枚举值、字段语义或必填性属于破坏性变化，必须同步更新本文、Rust DTO、TypeScript DTO、合同 fixture 和契约测试。
- 不为假设的未来客户端增加通用 envelope、Repository、SDK 或版本协商层；出现第二个真实 Adapter 且语义确有差异时再按第 14 节冻结新切片。
