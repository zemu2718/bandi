## 1. 判定规则

本矩阵把 9 个内置 AI 编程工具（Claude Code、Claude Desktop、Codex、Gemini、Grok、OpenCode、OpenClaw、Hermes、Pi）的页面承诺拆成可验证的长期 Agent / 配置管理切片，不记录任务、Session 或执行进度。

| 状态 | 含义 | UI 约束 |
| --- | --- | --- |
| `supported` | 有真实实现与可复现证据，满足当前切片合同 | 可提供主操作，但不得扩大证据含义 |
| `degraded` | 只覆盖部分路径，并有明确安全降级 | 必须说明限制和补救 |
| `unavailable` | 已确认当前实现不能完成 | 禁用操作并解释原因 |
| `not_checked` | 尚未执行真实验证 | 不得当作可用 |

页面文案、按钮可见、类型声明、演示资料和页面内存操作都不能单独证明真实系统能力。

## 2. Team、Agent 与 TaskBrief

| 能力切片 | 当前事实 | 状态 | 核心证据 | 明确边界 |
| --- | --- | --- | --- | --- |
| Personal Team | 新数据库和空状态稳定提供 `team-personal`，不可删除 | `supported` | Domain Store、长期领域快照与前端确定性回退测试 | Team 归属不自动扩大 Agent 长期权限 |
| Agent 单 Team 归属 | 每个长期 Agent 恰属一个 Team，归属只有一个事实源 | `supported` | AgentPackage identity、hydration 与 selector 测试 | 不维护第二个可漂移归属源 |
| Team 切换 | TeamSwitcher 收窄 Agent、TaskBrief 和 Team-scoped 长期资产 | `supported` | Team-scoped selectors、页面与 Chromium 键盘测试 | 不显示运行、在线、Session 或未读状态 |
| Agent 创建 | 创建 Agent 默认归入当前 Team，无组织前置 | `supported` | 受管 Agent 创建命令、页面测试与 Tauri E2E | 不重复询问 Team |
| TaskBrief | 可选创建且必须属于一个 Team，不持久化 Agent | `supported` | Team 关系校验、页面与 E2E | 只记录目标、背景、约束和期望产出；无进度、Todo、调度、审批、日志或验收状态 |

首版产品主线固定为：

```text
Team → Agent → 可选 Team-scoped TaskBrief
```

## 8. 合同测试最低集合

1. Rust、TypeScript 与 JSON Schema 对长期领域快照、`formal-memory-v4` 和 `client-launch-v3` 使用一致字段。
2. Personal Team 稳定存在；Agent 恰属一个 Team；两种 hydration 顺序结果一致。
3. Team 切换同步收窄 Agent、TaskBrief 和 Team-scoped 长期资产。
4. TaskBrief 只属于 Team，不持久化 Agent 或执行状态。
5. Agent 长期 Memory 完成安全直接写入、Revision 与 Recovery。
6. Client Launch v3 只准备上下文，请求和响应均不含路径或进程参数，任何分支都不启动外部进程。
7. Bandi 所有 API 均不接受、登记、扫描或访问任意用户目录；Factory Reset 不触碰 `~/.claude`。
8. 全部失败路径不产生 Task、Session、聊天、Todo、运行日志或伪造成功证据。

## 9. 变更规则

- 新增真实主操作前，先冻结类型化合同、信任边界和可复现证据；
- 状态提升必须补实现与测试，不能只修改文案；
- 新增客户端不自动获得探测、配置或启动能力；
- 不通过通用 `payload`、任意路径或通用进程 API 扩展首版；
- 首版配置范围只包括 Team、Agent、可选 Team-scoped TaskBrief 和 Agent 长期 Memory；
- `docs/archive/**` 仅用于历史追溯。
